# CyberRescue synthetic telemetry datasets

**SYNTHETIC data for testing and evaluation. This is not real telemetry.**
The hosts come from the mock asset inventory (`shared/mock_env/asset_inventory.json`).
Public IPs use documentation ranges, apart from the indicators already in the mock
alerts.

| Scenario | Dataset | Incident | Story |
|---|---|---|---|
| A | `scenario-a` | INC-C (`INC-C-2026-0042`) | Ransomware on the customer-PII database |
| B | `scenario-b` | INC-B (`INC-B-2026-0041`) | Suspected beaconing from the web frontend |
| C | `scenario-c` | INC-A (`INC-A-2026-0039`) | Commodity trojan on an engineering workstation |

```text
manifest.json                 generator version, seeds, sha256 and counts (no labels)
telemetry/<dataset>.jsonl     operational input: TelemetryEvent per line -> Evidence
ground_truth/<dataset>.json   EVALUATION ONLY: never ingested as evidence
```

The files are generated by `cyberrescue/telemetry/scenarios.py`. They must not be
edited by hand. To regenerate them, or to verify them byte for byte:

```powershell
python -m cyberrescue.telemetry generate
python -m cyberrescue.telemetry check      # exit 1 if any file differs
```

See `docs/cyberrescue/phase2b-telemetry.md`.
